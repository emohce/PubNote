# 固定守卫：会话标题 + 结构化回复

> 蒸馏自：session-title owner（含 details）与 communication-primary-response owner（含 details）。这两个是路由必派的 always-on 守卫。

## §title 会话标题

格式：

```text
yyMMdd[-PROJ][-WT]-扼要中文标题
```

| 字段 | 规则 |
| --- | --- |
| `yyMMdd` | 实测的 GMT+8 会话开始日期，永远在最前 |
| `PROJ` | 可选；任务稳定目标的缩写（有声明缩写用声明的，否则取分段首字母，2~4 字符）；没有稳定目标就省略 |
| `-WT` | 仅当实际在关联 worktree 执行时加；跨主线读取保留，确认回到主线后去掉 |
| 标题 | 6~12 个简体中文字符，半角连字符、无空格、无尾随日期 |

Apply Gate（执行时机）：

1. **第一轮就命名**：从初始请求推断意图，在第一个可用工具机会调用宿主改名 API——不等调查完、不等 worktree 建好。
2. **每轮重估**：任务目标/执行位置经证实变化时当轮改名；改名后同任务内回读校验。
3. **来源分类**：产品自动标题（首条消息生成的那种）视为 automatic 可覆盖；**用户手改的标题保留**，不覆盖。
4. **能力确认**：先解析当前宿主的改名通道。只生成计划不算完成，必须对同一对象回读。本会话没有改名工具时报告未测，不改产品数据库，不另造 API。

> 落地提示：宿主不支持改名时此守卫降级为"首轮在回复里给出一行建议标题"。

## §reply 结构化回复

默认语言：简洁简体中文，**先结论后证据**。代码、命令和标识符保持原文。终态回复默认 A–F 结构：

| 段 | 内容 |
| --- | --- |
| A | 目标/上下文/结果（保留） |
| B | 已跑检查 / 未跑的门禁 |
| C | 文档变更 |
| D | 提醒 / 材料限制 |
| E | 连续性（恢复点、待续事项） |
| F | 建议下一步及理由，或明确"无"（保留） |

规则：

- 空模块省略，但 A、F 一般保留。
- 编号：可引用的子项和表格行用 `1` / `1-A` 形式；模块字母是自动前缀（如 `B-1`）。无可编号的引用项视为不合格。
- 可读性：每行一个要点；模块间空行；子项用真实列表缩进（不用空格伪装）；≥2 个同形条目用表格；命令/路径/配置用代码围栏；不写密段落。
- 聊天中的文件跳转链接：**写入时实测的绝对路径 + 已验证行锚**；聊天里禁止相对链接（相对链接只允许出现在落盘文档内）。按当前宿主的跳转编码格式输出。
- 任务、进度、需求或设计、核验各自给一条链接，并写当前状态。进度播报简短；不强行抛问题。

## 为什么这两个是固定守卫

- 标题：让多会话/多 worktree 的可追溯性不依赖记忆——标题本身就是索引。
- 回复：结果先行 + 证据编号，使长任务链的每一步都能被引用和审计；A–F 结构保证"没跑的检查"和"下一步"不会被省略。
