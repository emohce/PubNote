# 密集行与展开式悬浮（Dense Rows And Hover Expansion）

本文件是跨项目**密集信息行**（明细表、审阅报告、对账清单、日志表）的行密度与展开行为 owner。
浮层的层级、落位与时序仍属 [contextual-help](contextual-help.md#L1)；本文件只管「一行里放多少、放不下怎么办、展开时页面能不能动」。

## 1. 稳定偏好

密集行的读者是来核对的，不是来被说服的：一屏能扫过的行数比单行信息量更重要。
一行按信息组切分（证据入口 / 状态与身份 / 分类 / 值 / 说明），**每个信息组在行内最多占两行文本**；
放不下的内容走截断 + 悬浮或详情，绝不靠撑高行来容纳。

## 2. 行内封顶

- 短列（分类名、分段名、证据入口、状态标）固定 `nowrap`。中文窄列一旦允许换行就会「单字成列」，读起来像竖排。
- 值区（芯片、键值对）按两行截断，其余靠悬浮展开；不要为了塞下全部值把行拉高。
- 说明优先压进一行；压不下按两行截断，全文进说明卡。禁止用原生 `title` 承载全文。
- 证据 / 打开原件 / 看图这类入口放在**行首固定列**：读者是先决定「要不要看证据」再看内容，入口排在行尾等于每次都要横扫过整行。

## 3. 展开式悬浮的实现范式

需要「悬浮才展开更多」的区域，用**定高外壳 + 内容常驻绝对定位**：

- 外壳始终占住封顶后的那两行高度，内容自始至终 `position: absolute`，常态被外壳裁剪。
- 悬浮只做两件事：解开裁剪、加卡片皮肤（底色、边框、投影、层级）。
- **反例（必须避免）**：悬浮时才把内容从 `static` 改成 `absolute`。内容在那一瞬间脱离文档流，宿主单元格塌陷，
  整表重排——鼠标进出各抖一次。这类抖动是缺陷，不是「动效」。

同一条口径适用于任何「常态收着、悬浮展开」的区域：标签堆、缩略图组、附件列表。

## 4. 重复文案的压缩

- **同因合并**：一段里被多个字段命中的同一句说明只写一次，命中字段名并列在前（`单位、数量：…`）。
  合并发生在**产出说明的那一处**，报告、弹窗与导出共用同一结论，不在各展示端各写一遍。
- **共同前缀提取**：一组条目共享的前缀提到标题或表头写一次，条目里只留区分部分。
- 结构已经表达的语义不再补一句文字；同一张表里不出现两处同义说明。

## 5. 验证

改动密集行后，至少记录三项可复现观测值：行数与行高分布、悬浮进出前后每行的 `[top, height]` 快照、
页面 `scrollWidth/scrollHeight` 是否变化。悬浮进出导致任一项变化即为未通过，不以「看起来还行」代替。
